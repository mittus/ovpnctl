# ovpnctl — мгновенный разворот готового OpenVPN сервера

Разворачивает OpenVPN-сервер на Debian/Ubuntu.

**Особенности:** сроки жизни всех сертификатов и CRL
контролируются systemd-таймером и продлеваются автоматически.

Поддерживаются Debian 10/11/12/13 и Ubuntu 20.04/22.04/24.04 (amd64/arm64).

---

## Установка

```bash
bash <(wget -qO- https://raw.githubusercontent.com/mittus/ovpnctl/master/install.sh)
```

| Параметр | Значение |
|---|---|
| Адрес сервера | внешний IP |
| Порт и протокол | `1194/udp` |
| VPN-подсеть | `10.8.0.0/24` |
| Ключи | EC `prime256v1` |
| DNS для клиентов | `1.1.1.1`, `1.0.0.1` |
| Сроки сертификатов | CA 20 лет, сервер и клиенты 10 лет, CRL 10 лет (автопродление) |

## Управление

```bash
ovpnctl                                    # интерактивное меню
ovpnctl status                             # сервер, сроки сертификатов, кто онлайн
ovpnctl doctor                             # самодиагностика: службы, NAT, форвардинг, PKI

ovpnctl client add <name>                  # новый клиент + профиль .ovpn
ovpnctl client add <name> --days 365 --ip 10.8.0.50
ovpnctl client list                        # таблица клиентов: сроки, адрес, общий трафик
ovpnctl client show <name>                 # вывести .ovpn в консоль
ovpnctl client renew <name>                # продлить сертификат
ovpnctl client revoke <name>               # отозвать (CRL + разрыв сессии)
ovpnctl client delete <name>               # отозвать и удалить все файлы
ovpnctl client ip <name> 10.8.0.50         # закрепить адрес в VPN-подсети

ovpnctl online                             # активные подключения
ovpnctl server restart|stop|start|config|logs|rebuild
ovpnctl set --endpoint vpn.example.com --port 443 --proto tcp --dns 9.9.9.9
ovpnctl ufw [--install] [--ssh] [--remove] # разрешить порт VPN в ufw
ovpnctl pki check|info|renew [--force]
ovpnctl backup                             # архив PKI + профилей + конфига
ovpnctl update [--check]                   # обновить ovpnctl из GitHub без переустановки
ovpnctl uninstall [--keep-pki] [--purge]
```

## Обновление

```bash
ovpnctl update           # или пункт 17 в меню
ovpnctl update --check   # только узнать, есть ли новая сборка
```

Скачивает свежий код из репозитория, откуда ставили (по умолчанию
`github.com/mittus/ovpnctl`, ветка `master`), и подменяет `/opt/ovpnctl`. Пакеты, PKI,
клиенты и настройки не трогаются. Затем новый код перегенерирует `server.conf`,
`firewall.sh` и юниты; OpenVPN перезапускается, только если эти файлы действительно
изменились. Неработающая сборка не ставится — перед подменой она пробно запускается.

Параметры: `--branch <ветка>`, `--repo <url>`, `--from <каталог или .tar.gz>` (без сети),
`--force` (переставить ту же сборку). Повторный запуск `install.sh` тоже обновляет код.

## Автопродление:

Таймер `ovpnctl-renew.timer` (ежедневно + через 10 минут после загрузки, со случайным
разбросом до 2 часов) запускает `ovpnctl pki renew --quiet`. Логика:

| Объект | Срок по умолчанию | Продлевается | Что происходит |
|---|---|---|---|
| CRL | 3650 дней | за 365 дней до конца, плюс обязательное обновление раз в 30 дней | перевыпуск, файл подхватывается сервером без рестарта |
| Сертификат сервера | 3650 дней | за 90 дней | перевыпуск **тем же ключом**, рестарт службы |
| CA | 7300 дней | за 365 дней | пересамоподписание **тем же ключом и subject** |
| Клиентские сертификаты | 3650 дней | за 30 дней | перевыпуск тем же ключом, профиль перегенерируется |

Ключевые решения, благодаря которым ротация ничего не ломает:

* **CA продлевается тем же ключом.** Subject и `subjectKeyIdentifier` не меняются,
  поэтому все ранее выданные сертификаты остаются валидными — перевыпускать клиентов
  не нужно.
* **В сертификатах нет `authorityKeyIdentifier: issuer+serial`,** только `keyid`.
  Иначе смена серийника CA при продлении сломала бы проверку цепочки (классическая
  ловушка, из-за которой «VPN внезапно перестал пускать»).
* **Уже розданные `.ovpn` продолжают работать после ротации CA:** в профиле лежит
  прежняя копия CA, а серверный сертификат подписан тем же ключом, поэтому клиент его
  по-прежнему принимает — до истечения именно этой копии. Продление CA запускается за
  год до конца срока, так что на раздачу обновлённых профилей есть год; профили
  перегенерируются автоматически, а в `renew.log` пишется крайняя дата.
  (В `<ca>` кладётся ровно один сертификат: OpenVPN не загружает два CA с одинаковым
  subject — «only 1 of 2 entries were valid X509 names».)
* **После продления CA выполняются проверки:** если хоть один действующий сертификат
  перестал проходить `openssl verify`, продление автоматически откатывается; отдельно
  проверяется, что старая копия CA всё ещё доверяет новому серверному сертификату.
* **CRL не даёт себя «протухнуть».** Просроченный CRL — самая частая причина отказа
  OpenVPN пускать клиентов; здесь он обновляется минимум раз в месяц.
* **Срок сертификата не переживает CA:** запрошенный срок автоматически подрезается
  остатком жизни CA, иначе `openssl` отказался бы подписывать.

Ручные проверки:

```bash
ovpnctl pki check            # таблица сроков и порогов
ovpnctl pki renew --force    # принудительно перевыпустить всё
systemctl list-timers ovpnctl-renew.timer
cat /var/log/ovpnctl/renew.log
```

Пороги и сроки правятся в `/etc/ovpnctl/config.json` (`ca_days`, `server_days`,
`client_days`, `crl_days`, `renew_*_before`, `auto_renew_clients`), после чего —
`ovpnctl server rebuild`.

## Структура

```
/opt/ovpnctl/lib/ovpnctl/     код менеджера (Python 3, только стандартная библиотека)
/usr/local/bin/ovpnctl        точка входа
/etc/ovpnctl/config.json      параметры сервера
/etc/ovpnctl/pki/             CA, ключи, сертификаты, CRL, база клиентов
/etc/ovpnctl/pki/archive/     прежние CA и сертификаты, заменённые при продлении
/etc/ovpnctl/profiles/        мастер-копии .ovpn (режим 0600, только root)
~/ovpnctl/                    выгруженные профили того, кто выполнял команду (владелец — он же)
/etc/ovpnctl/firewall.sh      правила NAT/forward (применяет ovpnctl-firewall.service)
/etc/ovpnctl/traffic.json     накопленный трафик клиентов по завершённым сессиям
/etc/ovpnctl/server.extra.conf   (опционально) свои директивы, добавляются в конец server.conf
/etc/openvpn/server/          рабочая копия конфига и материалов PKI для демона
/var/log/ovpnctl/renew.log    журнал автопродления
```

Юниты systemd: `openvpn-server@server.service` (штатный, с drop-in от ovpnctl),
`ovpnctl-firewall.service`, `ovpnctl-renew.timer` + `ovpnctl-renew.service`.

## Технические решения

* **Никакого easy-rsa.** Версии easy-rsa в Debian 10/11/12/13 и Ubuntu несовместимы между
  собой по флагам и умолчаниям; вместо неё — тонкий слой поверх `openssl` c собственным
  `openssl.cnf`. Результат одинаков на всех поддерживаемых системах.
* **Мультиверсионность OpenVPN.** Конфиг генерируется под найденную версию:
  `data-ciphers`/`allow-compression` для 2.5+, `cipher`/`ncp-ciphers` для 2.4;
  `openvpn --genkey secret` против старого `--genkey --secret`. В клиентских профилях
  новые директивы обёрнуты в `setenv opt`, поэтому файл не ломает старые клиенты.
* **Криптография.** По умолчанию EC-ключи (`prime256v1`), `dh none` (ECDHE),
  `tls-crypt` для защиты control-канала, `AES-256-GCM`, `tls-version-min 1.2`,
  `remote-cert-tls`/EKU в обе стороны. `--key-type rsa` — если нужны совсем старые клиенты.
* **`/run/openvpn-server` создаётся drop-in'ом** (`RuntimeDirectory=`): в Debian/Ubuntu
  этот каталог заводит `tmpfiles.d`, и без него служба не поднимается — туда пишутся
  status-файл и management-сокет.
* **Отзыв мгновенный.** `client revoke` обновляет CRL и через management-сокет рвёт
  текущую сессию клиента.
* **Общий трафик клиента.** При отключении клиента openvpn вызывает
  `/etc/openvpn/server/ovpnctl-traffic.sh` (`client-disconnect`), и тот дописывает байты
  сессии в `/etc/openvpn/server/traffic/sessions.log`. `ovpnctl` сворачивает журнал в
  `/etc/ovpnctl/traffic.json` и прибавляет текущую сессию из status-файла. Счётчик
  копится за всё время и сбрасывается только при `client delete`.

## Проверка кода

Юнит-тесты (ничего не трогают в системе — вся работа во временной песочнице, из
зависимостей нужен только `openssl`):

```bash
python3 tests/selftest.py        # 52 проверки
```

End-to-end в контейнере — три сценария: установка «одной командой» (скрипт сам качает
исходники), полный цикл (запуск демона, подключение реального клиента по `.ovpn`, экспорт,
отзыв, ротация CA) и работа с ufw:

```bash
bash tests/docker-e2e.sh debian:12                      # все сценарии
SCENARIOS="install" bash tests/docker-e2e.sh debian:12  # только один
```

Сетевой тест в трёх контейнерах и двух сетях (клиент, сервер, «интернет» за сервером) —
проверяет то, что внутри одного контейнера проверить нельзя: реальную пересылку трафика
через VPN, блокировку порта активным ufw и живучесть правил NAT после `ufw reload`:

```bash
bash tests/network-e2e.sh debian:12
```

Прогонялось на **Debian 13 (OpenVPN 2.6.14 / OpenSSL 3.5.1 / Python 3.13)**,
**Debian 12**, **Debian 11 (2.5.1 / 1.1.1n / 3.9)**, **Debian 10 (2.4.7 / 1.1.1n / 3.7.3)**
и **Ubuntu 22.04 (2.5.11 / 3.0.2 / 3.10)**: 57 юнит-проверок, 48 проверок установки,
62 — основного сценария, 23 — ufw-сценария и 11 — сетевого, все зелёные. В том числе
проверяется главное обещание: после `pki renew --force` (ротация CA + перевыпуск
серверного сертификата) профиль, выданный **до** ротации, продолжает подключаться.

`ovpnctl doctor` делает то же самое, но уже на живом сервере: службы, таймер, NAT,
форвардинг, наличие файлов PKI и сроки.

## Безопасность

Приватные ключи клиентов хранятся на сервере (`/etc/ovpnctl/pki/private/`), иначе
`ovpnctl client show` не смог бы восстановить профиль. Каталоги — `0700`, профили — `0600`.
Если такая модель не подходит, выпускайте клиентов из CSR вручную и удаляйте ключ с сервера
после выдачи профиля.

Резервная копия (PKI + профили + конфиг): `ovpnctl backup`. Восстановление — распаковать
архив в `/etc/ovpnctl` и выполнить `ovpnctl server rebuild`.

## Удаление

```bash
ovpnctl uninstall            # службы, правила, конфиги (с бэкапом в /root)
ovpnctl uninstall --purge    # плюс удалить пакет openvpn
bash uninstall.sh            # то же самое из исходников
```
